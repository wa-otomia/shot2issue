# shot2issue

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

スクリーンショットを撮って、注釈を加え、画像を埋め込んだ状態でそのまま GitHub / GitLab / YouTrack の issue にする Chrome 拡張機能（Manifest V3）です。ブラウザから離れることなく、しかも GitHub には Personal Access Token なしで issue を作成できます。

GitHub への送信には、お使いの既存の github.com セッションを利用します。作成・保管すべき Personal Access Token はありません。GitLab と YouTrack は、それぞれの REST API とトークンで連携します。バックエンドも解析・トラッキングもなく、すべてローカルで完結します。

TypeScript で書かれており、`build/` ディレクトリを生成してから読み込みます。

## 主な機能

- **複数のキャプチャ元。** 現在のタブはもちろん、画面全体・特定のウィンドウ・他のアプリも撮影できます（`chrome.desktopCapture`）。クリップボードの画像を貼り付けることも可能です（ポップアップの「クリップボードから貼り付け」、またはエディタ内で Ctrl/Cmd+V）。キャプチャ元ごとに個別のキーボードショートカットを割り当てられ、設定するとポップアップに表示されます。
- **1 つの issue に複数のスクリーンショット。** 撮影するたびにサムネイルが追加され、それぞれに注釈を付け、切り替え、不要なものは削除できます。送信時にはすべてがまとめて添付されます。エディタを開いたまま拡張機能アイコンを再度クリック（または貼り付け）すると、同じ issue に追加されます。
- **Canvas での注釈。** 矩形、番号付き枠（自動採番バッジ）、矢印、フリーハンドのペン、自動折り返し・サイズ変更可能なテキスト、そして機密情報を伏せるモザイク。Ctrl/Cmd+Z で元に戻し、Esc を 2 回押すとエディタを閉じます。注釈付き画像は PNG としてダウンロードするか、クリップボードへコピーできます。
- **複数の送信先に対応。** GitHub（トークン不要、既存の github.com セッションを利用）、GitLab（REST API + `api` スコープの PAT、セルフホスト対応）、YouTrack（REST API + 永続トークン）。各「ワークスペース」が 1 つのリポジトリ/プロジェクトを対象とします。YouTrack / GitLab の認証情報は再利用可能な「アカウント」に保存され、複数のワークスペースで共有できます（GitHub はアカウント不要）。設定は **ワークスペース / アカウント / AI / 一般 / 言語** のタブに整理されています。
- **任意の AI アシスタント。** OpenAI Codex / ChatGPT サブスクリプションでサインインすると（OAuth、従量課金の API キーは不要）、AI が支援します。「タイトル要約」は、説明文とスクリーンショットから issue のタイトルを生成します。「スマート口述」は、入力または口述した内容（音声はサブスクリプションで文字起こし）から、スクリーンショット内の番号付き枠を参照しつつ、タイトルと Markdown 本文を作成します。プロンプトは編集可能で、既定値への復元もできます。モデル一覧はライブで取得します。
- **テンプレートと多言語。** 既定のタイトル・本文テンプレートにプレースホルダー `{pageTitle}` `{pageUrl}` `{type}` を使えます。UI は英語・簡体中文・日本語に対応し、初回起動時にシステム設定から自動判定、設定で切り替え可能です。設定は JSON で書き出し・読み込みできます。
- **ローカル完結。** バックエンドなし、解析・テレメトリなし。すべてのデータはこのブラウザ内にとどまります。

## 動作要件

- Manifest V3 に対応した Google Chrome（または Chromium 系ブラウザ）。
- GitHub 送信先：同じブラウザで github.com にサインインしていること（対象リポジトリは非公開を含む）。
- GitLab 送信先：インスタンスの Base URL、プロジェクト、`api` スコープの Personal Access Token。
- YouTrack 送信先：インスタンスの Base URL、プロジェクト、永続トークン。

## インストール

ソースは TypeScript なので、読み込む前にビルドが必要です。

1. 本リポジトリをクローンまたはダウンロードします。
2. ビルドします。

   ```bash
   npm install
   npm run build
   ```

   TypeScript がコンパイルされ、静的アセットと合わせて `build/` ディレクトリが生成されます。
3. `chrome://extensions` を開きます。
4. 右上の「デベロッパーモード」を有効にします。
5. 「パッケージ化されていない拡張機能を読み込む」を選び、**`build/`** ディレクトリを指定します（リポジトリのルートでも `src/` でもありません）。
6. 初回インストール時に設定ページが開きます。ワークスペースを少なくとも 1 つ追加してください。

開発中は `npm run watch` で変更のたびに再コンパイルされます。反映するには `chrome://extensions` の拡張機能カードにある「更新」ボタンを押してください。更新しても設定は保持されます（拡張機能を削除すると消去されます）。

パッケージ済みのビルド（`dist/shot2issue-<version>.zip`、[ビルド](#ビルド)を参照）も同じ方法で読み込めるほか、Chrome Web Store へのアップロードにも使えます。

## 使い方

1. 撮影したいページを開き、shot2issue のツールバーアイコンをクリックします。表示領域が撮影され、新しいタブでエディタが開きます。
2. エディタでワークスペースと種類を選び、スクリーンショットに注釈を加え、タイトルと説明を編集します。タイトルの既定値は「ページタイトル + 選択した種類」、本文の既定値はページ URL です。
3. 「issue を送信」をクリックします。拡張機能が対象リポジトリの新規 issue ページをバックグラウンドのタブで開き、スクリーンショットをアップロードし、フォームを入力して送信します。成功すると issue へのリンクが表示されます（有効にしている場合は撮影元のページに戻ります）。

送信に失敗した場合は、「PNG をダウンロード」で注釈付き画像を保存して手動で添付するか、「スクリーンショットなしで送信」で画像を添付せずに issue を作成できます。

## 設定

設定ページは `chrome://extensions`（詳細 → 拡張機能のオプション）またはエディタの「設定」リンクから開けます。設定は **ワークスペース** / **アカウント** / **AI** / **一般** / **言語** のタブに分かれています。

- **アカウント** —— YouTrack / GitLab インスタンスの再利用可能な認証情報です。表示名・Base URL・トークン（YouTrack の永続トークン、または `api` スコープの GitLab Personal Access Token）を保存します。同じインスタンス上の複数のワークスペースが 1 つのアカウントを共有します。GitHub はアカウント不要です（github.com のウェブセッションを使用）。アカウントはローカルに保存され、設定のバックアップに含まれます。
- **ワークスペース** —— 各ワークスペースは 1 つの送信先です。GitHub では表示名・owner（ユーザーまたは組織）・リポジトリ名を、YouTrack / GitLab では表示名・アカウント（「アカウント」タブで選択）・プロジェクト（YouTrack の短縮名/id、または GitLab の数値 id か `group/project` パス）を指定します。認証情報をインラインで保存していた旧 YouTrack ワークスペースは、自動的にアカウントへ移行されます。
- **種類** —— エディタの「種類」ドロップダウンに表示され、既定タイトルに使われます。既定値は Change、Bug、Feature。
- **既定のタイトルと本文** —— 新規 issue を事前入力するテンプレート。プレースホルダーは `{pageTitle}`、`{pageUrl}`、`{type}`。
- **AI アシスタント** —— 任意で OpenAI Codex / ChatGPT のアカウントでサインインし、タイトルを生成できます。下記の [AI アシスタント](#ai-アシスタント) を参照してください。
- **動作** —— 送信成功後にエディタを閉じて撮影元のページに戻るかどうか。
- **キーボードショートカット** —— 任意でショートカットから撮影できます（既定では無効）。ここで有効化したうえで、Chrome のショートカットページ（`chrome://extensions/shortcuts`、「ショートカットを設定」ボタンで開きます）でキーの組み合わせを割り当てます。
- **言語** —— 英語、簡体中文、日本語。初回起動時にシステム設定から自動判定されます。
- **バックアップ / 復元** —— 設定を JSON ファイルに書き出し、後で読み込めます。設定はこのブラウザ内（`chrome.storage.local`）にのみ保存されます。

## 送信の仕組み

- **GitHub** —— お使いの既存の github.com セッションを利用するため、Personal Access Token は不要です。対象リポジトリの新規 issue ページをバックグラウンドのタブで開き、タイトルと説明を入力し、スクリーンショットをページにアップロードして送信します。アップロードは GitHub 自身のページコードが実行するため、添付は issue にインライン埋め込みされます。
- **YouTrack** —— 文書化された REST API を永続トークンで直接利用します。issue を作成し（`POST /api/issues`）、スクリーンショットをアップロードして（`POST /api/issues/{id}/attachments`）ファイル名でインライン埋め込みします。
- **GitLab** —— こちらも文書化された REST API を使います。アカウントの Personal Access Token（`PRIVATE-TOKEN` ヘッダー、`api` スコープ）で各スクリーンショットをプロジェクトにアップロードし（`POST /api/v4/projects/:id/uploads`）、返ってきた markdown を本文に埋め込んで issue を作成します（`POST /api/v4/projects/:id/issues`）。プロジェクトは数値 id か URL エンコードした `group/project` パスで指定でき、セルフホスト環境はアカウントの Base URL で動作します。

YouTrack / GitLab のインスタンス URL は事前に分からないため、各インスタンスへの初回送信時に、そのオリジンへのアクセス許可を求めます。

## AI アシスタント

任意の AI アシスタントは、OpenAI Codex / ChatGPT サブスクリプションのアカウントでサインインして利用します（OAuth、PKCE）。従量課金の API キーではなく、お使いのサブスクリプションを使います。接続するまでは無効で、データが送信されることもありません。

- **タイトル要約** —— エディタで、現在の種類・ページタイトル・ページ URL・説明・スクリーンショットから issue のタイトルを生成します。モデル一覧は Codex の models エンドポイントから動的に取得します（組み込みのフォールバックあり）。
- **スマート口述** —— ダイアログで説明を入力するか、録音して口述できます（録音は ChatGPT サブスクリプションで文字起こしされます）。モデルがそのテキスト・スクリーンショット・ページのメタデータからタイトルと Markdown 本文を作成し、スクリーンショット内の番号付き枠を番号で参照します。ダイアログの内容は再オープン後も保持され、繰り返し生成できます。

タイトル用・口述用のシステムプロンプトはいずれも設定で編集でき、それぞれ「既定のプロンプトに戻す」ボタンで現在のインターフェース言語の既定値にリセットできます。

> 注意：本アシスタントは変更される可能性のある `chatgpt.com` のエンドポイントと通信し、お使いのアカウントに対する OpenAI の規約が適用されます。トークンは `chrome.storage.local` にのみ保存され、設定のバックアップには一切含まれません。

## 権限

| 権限 | 用途 |
| --- | --- |
| `activeTab` | アイコンのクリック時に付与。表示中のタブを撮影し、タイトルと URL を読み取るために使用。 |
| `storage` | 設定と保留中のスクリーンショットを `chrome.storage.local` に保存。 |
| `unlimitedStorage` | 全画面・複数画像のキャプチャを `storage.session` の小さなクォータに引っかからずに一時保存できるようにします。一時保存した画像は送信後とエディタを閉じたときに削除されます。 |
| `scripting` | github.com タブに送信用スクリプトを、画面/ウィンドウのキャプチャ時にはアクティブタブにフレーム取得スクリプトを注入。 |
| `desktopCapture` | 「画面またはウィンドウ」を選んだときに選択ダイアログを表示。このキャプチャ元でのみ使用。 |
| `clipboardRead` | 「クリップボードから貼り付け」とエディタの貼り付け機能のために、クリップボードの画像を読み取り。 |
| `notifications` | キャプチャの失敗（画面キャプチャを含む）などをシステム通知で表示。 |

ホスト権限は既定で `https://github.com/*` のみで、これが GitHub 送信時の唯一の通信先です。スクリーンショットのバイト列は GitHub 自身のページコードがそのストレージへアップロードするため、拡張機能はそれらのストレージホストの権限を必要としません。

YouTrack / GitLab のインスタンス URL は事前に分からないため、`optional_host_permissions` として宣言し、実行時に要求します。あるインスタンスに初めて保存または送信するとき、Chrome がそのオリジンへのアクセス許可を求めます。AI アシスタントも同様に、接続時に `https://auth.openai.com/*`・`https://chatgpt.com/*`・`http://localhost:1455/*`（サインインのコールバックを読み取るため）を要求します。

## プライバシー

- 使用するのはスクリーンショット、タイトル、説明、現在のページ URL のみです。コンソール出力、ネットワーク活動、デバイス情報は収集せず、テレメトリも含みません。
- GitHub 送信ではトークンを保存せず、既存の github.com セッションに依存します。YouTrack / GitLab のトークンはこのブラウザ内（`chrome.storage.local`）にのみ保存されます。
- AI アシスタントは接続するまで無効です。「タイトル要約」を使用すると、種類・説明・ページ URL・現在の（注釈付き）スクリーンショットが、タイトルを生成するために OpenAI へ送信されます。「スマート口述」ではさらに録音した音声が文字起こしのために送信されます。AI のトークンは `chrome.storage.local` にのみ保存され、設定のバックアップから除外されます。
- 添付の公開範囲はリポジトリの公開範囲に従います。非公開リポジトリの添付は閲覧にサインインが必要で（2023-05 以降）、公開リポジトリの添付は匿名で閲覧できます。対象リポジトリは用途に応じて選んでください。
- モザイクツールは伏せ字に使えます。送信前に機密情報を覆ってください。元のスクリーンショットをサンプリングし、選択した領域をピクセル化します。

## プロジェクト構成

`src/` に TypeScript ソースと静的アセットが置かれています。ビルドするとこれらが `build/`（「パッケージ化されていない拡張機能を読み込む」の対象）にコンパイルされ、リリース用の zip は `dist/` に出力されます。

```
shot2issue/
├── src/                          # TypeScript ソースと静的アセット
│   ├── manifest.json            # MV3 マニフェスト。github.com ホスト権限 + 任意の YouTrack/GitLab オリジン
│   ├── background.ts            # service worker：アイコン/ショートカットで撮影しエディタを開く
│   ├── editor.ts / .html / .css # メイン UI：選択、Canvas 注釈、送信
│   ├── options.ts / .html       # 設定：ワークスペース、種類、言語、ショートカット、バックアップ
│   ├── lib/
│   │   ├── storage.ts           # chrome.storage アクセス（設定 + 保留中のスクリーンショット）
│   │   ├── i18n.ts              # インターフェース文字列（en / zh / ja）
│   │   ├── github-attach.ts     # github.com サインイン検出
│   │   ├── page-upload.ts       # GitHub：github.com のウェブフォームによるページ内送信
│   │   ├── youtrack.ts          # YouTrack：REST API による issue 作成と添付アップロード
│   │   └── providers/
│   │       ├── index.ts         # プロバイダーのレジストリ
│   │       ├── types.ts         # Provider インターフェースと共有型
│   │       ├── github.ts        # GitHub プロバイダー
│   │       └── youtrack.ts      # YouTrack プロバイダー
│   └── icons/                   # 16 / 48 / 128 px アイコン
├── scripts/copy-assets.mjs      # 静的アセットを build/ へコピー
├── package.json                 # npm スクリプト：build、watch、typecheck
├── tsconfig.json                # TypeScript コンパイラ設定
├── build/                       # コンパイル成果物（load unpacked の対象、生成物）
├── dist/                        # リリース用 zip（生成物）
├── Dockerfile                   # リリースアーカイブ用の Docker ビルド
├── .github/workflows/build.yml  # CI：Docker ビルド、artifact のアップロード、release への添付
├── LICENSE
└── README.md
```

## ビルド

「パッケージ化されていない拡張機能を読み込む」には、まず TypeScript をコンパイルする必要があります。

ローカルでビルドする場合：

```bash
npm install && npm run build
# 出力：build/（load unpacked の対象）
```

ローカルにツールチェーンを用意せず、リリース用アーカイブを生成する場合は Docker を使います。

```bash
docker build --target export --output type=local,dest=dist .
# 出力：dist/shot2issue-<version>.zip
```

継続的インテグレーション（[`.github/workflows/build.yml`](.github/workflows/build.yml)）は、`main` へのプッシュ、Pull Request、手動実行のたびに Docker ビルドを実行し、アーカイブを workflow artifact としてアップロードします。`v*` タグのプッシュでは、アーカイブを GitHub release にも添付します。

```bash
git tag v1.0.0 && git push origin v1.0.0
```

## テスト

Playwright のスモークテスト（[`tests/smoke.mjs`](tests/smoke.mjs)）は、ビルド済みの拡張機能を読み込み、拡張機能内の画面を検証します。設定ページのプロバイダーごとのフィールド切り替えと i18n、エディタの注釈ツール（矩形、ペン、透過テキスト）、元に戻す、Esc での終了などです。実際の GitHub / YouTrack への送信は、本物のアカウントとセッションが必要なため対象外です。

```bash
npm run build
npx playwright install chromium   # 初回のみ
xvfb-run -a npm test              # ディスプレイのない Linux 環境の場合（それ以外は npm test）
```

README のスクリーンショットも同様に `npm run screenshots` で生成できます。

## issue バックエンドの追加

送信先のバックエンドはプロバイダーとして実装されています。新しいバックエンドを追加するには、[`src/lib/providers/types.ts`](src/lib/providers/types.ts) の `Provider` インターフェースを実装したモジュールを `src/lib/providers/` に作成し、[`src/lib/providers/index.ts`](src/lib/providers/index.ts) のレジストリに登録します。プロバイダーは設定フィールド・ワークスペースの検証・必要なホスト権限の要求・`submit()` の実装を持ち、エディタと設定ページがレジストリからそれらを読み込みます。

## 制限事項

- 表示領域のみを撮影します。ページ全体やスクロールを伴う撮影には対応していません。
- `chrome://` や Chrome Web Store などの制限付きページは撮影できません（エディタがその旨を表示します）。
- ラベルの自動設定は行いません。
- GitHub への送信フローは現在のウェブ UI に依存しており、UI の変更時に更新が必要になる場合があります。
